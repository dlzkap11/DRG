# 15. TC 구글 시트: 제목 변경과 M4·M5 케이스 추가

- 날짜: 2026-10-28
- 브랜치: `docs/tc-sheet-m4-m5` (이 기록과 PROGRESS만 저장소에 남는다. TC 자체는 구글 시트에서 수정했다.)
- 대상: [DRG QA 테스트 케이스](https://docs.google.com/spreadsheets/d/11lkFmi72EjsPGOmwJ1PIUSr4UkklRXhGDEYqfu55EC0/edit) (구글 시트)
- 기준: DEC-008·DEC-009·DEC-010, DevLog 11·13

## 배경
- 소유자는 TC를 저장소의 `Docs/QA/*.md`가 아니라 이 구글 시트로 관리하기로 했다.
- 시트는 원래 "DRG M3 QA 테스트 케이스"(사람 1 + 봇 1, 40개)라서 M4·M5 내용이 없었다.
- 몇몇 케이스는 M5에서 바뀐 흐름과 맞지 않았다: 실행하면 바로 전투 화면이 뜨는 것으로 되어 있었고, Play Again 버튼을 가정했다.

## 변경 내용
1. **노란 입력칸 색 낮춤**: 진행 현황 B3:B5(빌드 버전, 테스트 일자, 테스터)의 배경을 `#FFFF00`에서 `#FFF2CC`로 바꿨다.
2. **파일 제목**: "DRG M3 QA 테스트 케이스"를 "DRG QA 테스트 케이스"로 바꿨다. 링크는 그대로다.
3. **진행 현황**:
   - 제목을 "DRG QA 진행 현황"으로 바꾸고, 대상 설명을 로비 → 게임(AI 1~7) → 결과로 고쳤다.
   - TC_전투, TC_행동제한, TC_UI는 로비에서 AI 1명으로 진행한다고 적었다.
   - 집계 표에 TC_다인전, TC_로비결과 행을 추가했다. 기존 행과 같은 COUNTA/COUNTIF 수식을 썼고, 합계 범위 안에 행을 넣어 합계가 자동으로 포함한다.
4. **새 탭 TC_다인전 (M4, MP-01~15)**:
   - 8인 카드 배치, 모든 봇 행동 숨김, 대상 7명, 탈락한 봇이 대상에서 빠지는지
   - Reveal 패널(판정 결과만), 피해 누적, 정확한 상쇄, 동시 탈락, 봇 대상 분산
   - 관전 화면, 관전 중 Next Turn, Skip to End, 생존 중 Skip 숨김, Skip 연타, 판정 줄이 많을 때 배치
5. **새 탭 TC_로비결과 (M5, LR-01~15)**:
   - 로비 초기 상태, AI 추가 한도(7), 제거와 0명, Ready 토글, AI 0명이면 시작 불가
   - 고른 인원으로 시작, Start 연타
   - See Results, 승리·패배 결과, 공동 순위, 무승부 결과
   - 로비 복귀(봇 수 유지, Ready 다시), 연속 순환, 8명 순위표 배치
6. **기존 케이스 수정**:
   - TC_UI UI-01: 사전 조건을 "로비에서 AI 1명, Ready → Start"로 고쳤다.
   - TC_UI UI-10: 종료 패널 버튼을 See Results로 고쳤다.
   - TC_UI UI-11: "결과 화면을 거쳐 새 게임 시작"으로 다시 썼다.
   - CL_스모크 1: 실행하면 로비가 뜨는 것으로 고쳤다.
   - CL_스모크 7: 결과 → 로비 → 새 게임 흐름으로 고쳤다.
   - CL_스모크 9·10: AI 7명 게임, 탈락 후 관전 항목을 추가했다.
7. 새 탭은 TC_UI를 복제해서 만들었다. 그래서 열 너비, 머리글, 결과 드롭다운(Pass/Fail/Block/N/A), 결과 색 조건부 서식이 기존과 같다. 새 행에도 위 행과 같은 서식(줄바꿈, 위쪽 정렬)을 적용했다.

## 검증
- 진행 현황을 다시 읽어 확인했다.
  - 탭별 전체 수가 맞다: 14, 6, 12, 15, 15, 10.
  - 합계는 72개, 수식 오류는 없다.
- 새 탭의 마지막 행(16행)에 줄바꿈과 결과 드롭다운이 적용된 것을 확인했다.
- CL_스모크 새 행(11행)도 확인했다.
- 케이스 문구에 쓴 화면 문자열은 M4·M5 코드와 대조했다(`You are eliminated - spectating`, `No attacks this turn.`, `See Results`, `Back to Lobby`, `Add at least one AI to start.` 등).
- 이 작업은 실제 빌드를 실행해 보지 않았다. 케이스의 실제 결과는 테스트할 때 시트의 결과 열에 기록한다.

## 남은 문제
- 저장소의 `Docs/QA/*.md`(UI 수동 TC, M3 체크리스트)는 이제 시트와 따로 놀 수 있다. 지울지, 안내만 남길지는 소유자가 정한다. §26 추적표처럼 자동 테스트와 연결된 문서는 저장소에 두는 것을 제안했다.
- 소유자 화면 확인(`build5`) 시 이 시트로 결과를 기록하면 M3·M4·M5 완료 판정 근거가 된다.
