# DRG 개발 작업 기록 (DevLog)

개발 단계마다 무엇을, 왜, 어떻게 했는지 남기는 폴더입니다.

- 게임 규칙의 기준은 여전히 기획서, 명세서, `DECISIONS.md`입니다. 이 폴더는 **작업 기록**일 뿐 규칙을 정하지 않습니다.
- 마일스톤 체크 상태는 `Docs/PROGRESS.md`에서 관리합니다.

## 작성 규칙
- 작업 1건마다 파일 1개를 만듭니다. 파일 이름은 `NN_제목.md`이고 번호는 순서대로 붙입니다.
- 각 문서에는 다음 항목을 적습니다.
  1. 목표
  2. 참고한 문서와 파일
  3. 변경한 파일
  4. 구현 내용과 설계 판단
  5. 검증 방법과 결과
  6. 남은 문제와 설계 질문
  7. 다음 단계
- 실제로 실행하지 않은 테스트나 검증은 "실행함"으로 적지 않습니다.

### 마일스톤 요약 문서
- 마일스톤(M1, M2, …)이 끝날 때마다 `M<번호>_요약.md`를 하나 만듭니다. 단계별 문서를 모두 읽지 않아도 전체를 파악할 수 있게 하는 문서입니다.
- 요약 문서에는 다음 항목을 적습니다.
  1. 한 줄 요약, 기간, 커밋 범위, 단계별 문서 링크
  2. 구현한 구조 (흐름도, 클래스 역할과 위치)
  3. 구현된 규칙이나 기능 정리
  4. 이 마일스톤에서 확정된 설계 결정 (DECISIONS.md 링크)
  5. 테스트 현황과 실행 방법
  6. 진행 과정 (단계, 브랜치, 커밋)
  7. 남은 설계 질문
  8. 다음 단계 후보
- 요약 문서에는 단계별 문서, DECISIONS, PROGRESS, 코드에 이미 있는 내용만 정리합니다. 새로운 규칙은 적지 않습니다.
