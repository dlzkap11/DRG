# 16. 빌드를 창 모드로 실행하고 창 크기 조절 허용

- 날짜: 2026-10-28
- 브랜치: `feature/windowed-resizable`
- 바꾼 파일: `ProjectSettings/ProjectSettings.asset` (Player 설정 5줄)

## 배경
- 소유자가 `build5/DRG.exe`를 실행하면 전체 화면으로 떴다.
- 소유자는 처음부터 창 모드로 뜨고, 창 크기를 마우스로 조절할 수 있기를 원했다.
- 원래 Player 설정은 `fullscreenMode: 1`(전체 화면 창), `resizableWindow: 0`, 기본 해상도는 모니터 해상도(`defaultIsNativeResolution: 1`)였다.

## 변경 내용
| 설정 | 이전 | 이후 |
|---|---|---|
| `fullscreenMode` | 1 (FullScreenWindow) | 3 (Windowed) |
| `resizableWindow` | 0 | 1 |
| `defaultIsNativeResolution` | 1 | 0 |
| `defaultScreenWidth` × `Height` | 1920 × 1080 | 1280 × 720 |

- 창 기본 크기는 UI 기준 해상도(`DRGPanelSettings`의 1280×720)와 맞췄다.
- UI는 Scale With Screen Size(match 0.5)라서 창 크기를 바꾸면 화면 전체가 함께 커지거나 작아진다.
- `allowFullscreenSwitch: 1`은 그대로라서 Alt+Enter로 전체 화면과 창 모드를 오갈 수 있다.
- 게임 코드는 바꾸지 않았다.

## 검증
- Unity 6000.3.22f1 `-batchmode -buildWindows64Player`로 빌드했다: `Build Finished, Result: Success`.
- 이번 빌드부터 위치를 임시 폴더가 아닌 프로젝트의 `Builds/DRG.exe`로 바꿨다(`.gitignore`가 `/Builds/`를 제외한다).
- 빌드할 때 Unity가 다시 저장한 관계없는 파일(URP 설정 3개, `UnityConnectSettings.asset`, `ProjectSettings.asset`의 `m_BuildTargetBatching`)은 되돌렸다.
- **확인하지 못한 것**: 실행한 창의 실제 크기와 크기 조절 테두리는 자동으로 확인하지 못했다. 소유자가 직접 실행해서 확인한다.

## 남은 문제
- Unity는 마지막 창 모드와 크기를 레지스트리(`HKCU\Software\DefaultCompany\DRG`)에 저장한다. 기본값이 바뀌면 저장값을 새로 쓰지만, 그래도 전체 화면으로 뜨면 Alt+Enter로 창 모드로 바꾸면 다음 실행부터 창 모드가 유지된다.
