# 04. M1 마무리: TurnManager와 BattleResolver 연결

- 날짜: 2026-09-28
- 브랜치: `feature/m1-turn-resolution`
- 마일스톤: M1 전투 로직 기초 (이번 작업으로 완료)
- 기준: 기획서 §2 핵심 게임 루프 / 명세서 §10, §11, §25 / `CLAUDE.md` §5 아키텍처 흐름

## 목표
STEP 3까지 `BattleResolver`는 따로 떨어져 있었고, `TurnManager.StartResolution()`은 상태만 바꿨다. 이번 작업의 목표는 두 가지다.
- 기획서의 핵심 루프(행동 선택 → Lock → 동시 해결 → 탈락 → 승리 확인 → 다음 턴)가 `TurnManager` 하나로 끝까지 돌아가게 한다.
- 승리나 무승부가 나오면 다음 턴이 시작되지 않게 한다.

## 구현 내용과 설계 판단
- **`StartResolution()`의 반환값 변경** (`void` → `BattleResult`)
  - 전원 Lock을 확인하고 상태를 `ActionResolution`으로 바꾼다.
  - 그다음 `BattleResolver.ResolveTurn(players)`를 호출해 결과를 돌려준다.
  - 결과 연출(Presentation)은 이 결과를 받아 재생하고, 끝나면 `EndTurn()`을 부른다. `CLAUDE.md` §5의 흐름(TurnManager → BattleResolver → BattleResult → BattlePresentation)을 따른 것이다.
- **`IsGameOver` 추가**
  - 결과가 `Winner`나 `Draw`이면 `true`가 된다.
  - `IsGameOver`인 상태에서 `StartTurn()`을 부르면 `InvalidOperationException`을 던진다.
  - `EndTurn()`은 게임이 끝난 뒤에도 부를 수 있다. 마지막 턴의 연출을 끝내고 `TurnEnd` 상태로 정리하기 위해서다.
- **BattleResolver 생성 위치**: `TurnManager` 생성자에서 `GameSettings`로 만든다. 새 추상화나 주입 구조는 만들지 않았다.
- **GameState 전환은 하지 않음**: 게임이 끝났을 때 `GameState`를 `Result`로 바꾸는 일은 GameState를 누가 관리할지가 정해지지 않아서 하지 않았다(PROGRESS 설계 질문). `IsGameOver`와 `BattleResult.Outcome`만으로 호출하는 쪽이 판단할 수 있다.
- **새 게임 규칙 없음**: "승리 확인 후 게임 종료"는 기획서 §2 루프에 이미 있는 내용이다. 그래서 DECISIONS에 추가할 항목이 없다.

## 검증
- Unity 6000.3.22f1을 커맨드라인으로 실행했다: `-batchmode -nographics -runTests -testPlatform EditMode`
- 결과: **79개 중 79개 통과**, 실패 0. 컴파일 오류·경고 0건.
  - ActionValidatorTests 25개, BattleResolverTests 29개: 이번에도 모두 통과
  - TurnManagerTests 25개: 기존 19개 + 이번에 추가한 6개
    - `StartResolution`이 Lock된 행동을 실제로 처리함: HP·Ki 변화, 데미지 결과, 게임 계속 진행
    - 게임이 계속 진행 중이면 다음 턴을 시작할 수 있음
    - 승리 시 게임 종료: `IsGameOver`가 되고 다음 `StartTurn`에서 예외
    - 무승부 시 게임 종료: 위와 같음
    - 이번 턴에 탈락한 플레이어는 다음 턴에 자동으로 None Lock되고, 공격 대상으로 지정할 수 없음
    - 6턴짜리 게임을 처음부터 끝까지 진행: 데미지 누적, 이번 턴에 탈락하는 플레이어의 공격 적용, 탈락자 자동 Lock, 승자 결정
- 테스트 작성 중 발견해서 고친 것:
  - 처음 짠 풀게임 시나리오의 턴 4에서 B→C와 C→B가 서로를 겨누는 에너지파라서 상쇄되는 조합이었다. 기대값이 규칙과 맞지 않았다.
  - 게임 도중에 Ki를 직접 바꾸는 부분도 있었다.
  - 테스트를 돌리기 전에 발견했고, 실제 규칙대로만 흘러가는 6턴 시나리오로 다시 짰다. 구현 코드는 바꾸지 않았다.
