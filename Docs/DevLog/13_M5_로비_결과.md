## 목표
명세서의 프로토타입 흐름 "로비 → AI 추가 → 게임 시작 → … → 승자 → 결과 → 로비"를 실제 씬 3개로 연결한다.

## 작업 전에 확정한 사항 (프로젝트 소유자 결정 → DEC-010)
| 질문 | 결정 |
|---|---|
| 씬 구성 | 명세서대로 LobbyScene / GameScene / ResultScene 3개. 순수 C# `GameFlow`가 GameState와 씬 사이 데이터를 맡는다. |
| 로비 범위 | 로비와 방을 한 화면에 최소 기능으로 둔다: 참가자 목록, AI 추가·제거, Ready, Start. 캐릭터 선택은 기본 캐릭터 1종이라 만들지 않는다. |
| 결과 화면 | 승자(또는 무승부), 진행 턴 수, 탈락 순서 순위. 같은 턴에 탈락하면 공동 순위. |
| 전적 저장 | 이번에는 제외한다. 무승부를 어떻게 셀지 먼저 정해야 한다. |

게임 규칙은 바꾸지 않았다.

## 구조
```text
LobbyScene ── LobbyScreen ─ LobbyView ─ Room          GameFlow.OpenRoom()      (GameState: Lobby → Room)
   │ Start (봇 1명 이상 + 내가 Ready)                  GameFlow.StartGame()     (Room → Game)
   ▼
GameScene ── BattleScreen ─ BattleView ─ LocalBattleSession(봇 수 = GameFlow.BotCount)
   │ 게임 종료 → "See Results"                         GameFlow.FinishGame(GameResultSummary)  (Game → Result)
   ▼
ResultScene ── ResultScreen ─ ResultView ─ GameFlow.LastResult
   │ "Back to Lobby"                                   GameFlow.ReturnToLobby() (Result → Lobby)
   ▼
LobbyScene (직전 봇 수 유지, Ready는 다시 눌러야 함)
```

## 구현 내용과 설계 판단
- **GameFlow (순수 C#)**:
  - 상태는 Lobby → Room → Game → Result → Lobby 순서로만 바뀐다. 순서를 어기면 `InvalidOperationException`을 던진다.
  - 씬이 바뀌어도 유지되도록 프로세스 전역 인스턴스 `GameFlow.Current`를 둔다. 플레이를 시작할 때마다 Unity가 도메인을 다시 불러오므로 매번 초기화된다.
  - 테스트는 각자 새 인스턴스를 만들어 쓴다.
  - "GameState를 누가 관리하나" 질문이 이것으로 해결됐다.
  - 전투 세션은 GameFlow가 Game 상태일 때만 생긴다. 그래서 명세서 §9의 "현재 GameState에서 행동 가능 여부"는 구조적으로 보장된다. Lock 자체는 여전히 TurnState로 판단한다.
- **Room**:
  - 방장은 사람(`You (Host)`)이다. 봇은 `Bot 1`~`Bot N` 순서로 추가되고, 제거는 마지막 봇부터 한다.
  - 봇은 항상 Ready이고, 사람은 Ready를 직접 누른다.
  - 시작하려면 봇이 1명 이상이고 사람이 Ready여야 한다(기획서 §10 "모든 참가자가 Ready이고 방장이 시작").
  - 봇 이름은 `LocalBattleSession`이 만드는 이름과 같다.
- **결과 순위 (`GameResultSummary`)**:
  - 생존자가 1위다. 그다음은 늦게 탈락한 순서다.
  - 같은 턴에 탈락하면 공동 순위이고, 다음 순위는 그 인원만큼 건너뛴다(1, 2, 2, 4).
  - 무승부일 때는 마지막 턴에 함께 탈락한 플레이어들이 공동 1위가 된다.
  - 탈락 턴은 `LocalBattleSession`이 전투를 처리할 때 `EliminatedPlayerIds`로 기록한다.
  - 기록 없이 이미 탈락 상태인 플레이어(테스트 준비용)는 0턴으로 본다.
- **GameScene 단독 실행**: 에디터에서 GameScene만 열고 Play를 눌러도 동작한다. `BattleScreen`이 GameFlow를 Room → Game까지 자동으로 진행시키고, 씬에 저장된 `botCount`(1)를 쓴다.
- **M4 설정 패널 제거**: 봇 수 선택은 로비로 옮겼다(DEC-009에서 예고). 게임 종료 패널의 "Play Again"은 "See Results"로 바꿨다.
- **씬 자동 생성 버그 수정 (작업 중 발견)**:
  - 처음 만든 빌더는 PanelSettings를 한 번 불러와 씬 3개에 같이 넣었다.
  - 그런데 두 번째 씬을 만들 때 그 객체가 메모리에서 내려가서, GameScene과 ResultScene의 PanelSettings 참조가 비었다(`{fileID: 0}`). 첫 씬(Lobby)만 정상이었다.
  - 씬 참조 테스트 2개가 실패해서 발견했다. 씬마다 PanelSettings를 다시 불러오도록 고쳤다.

## 검증
- EditMode 테스트: **161개 중 161개 통과**, 컴파일 오류·경고 0건
  - M4 기준 137개에서 설정 패널 테스트 4개를 삭제하고 28개를 추가했다.
  - `LobbyFlowTests` (15)
    - Room: 방장과 봇의 Ready 상태, 봇 수 0~7 범위, 처음 봇 수 범위 제한, 시작 조건
    - GameFlow: 전체 순환, 새 방은 직전 봇 수를 유지하고 Ready는 다시 해야 함, 시작 조건을 어기면 예외, 순서를 어기면 예외, 끝나지 않은 결과는 거부
    - 순위: 승자 1위와 탈락 순서, 같은 턴 공동 순위(1·2·2·4), 무승부 공동 1위, 실제 8인 게임(사람이 처음부터 탈락)의 순위와 탈락 턴이 맞는지
  - `LobbyResultViewTests` (10): **실제 UXML**로 확인했다.
    - 로비: 참가자 표시와 Ready 토글, AI 추가·제거 한도, Start 조건
    - 결과: 제목, 턴 수, 순위 행, 승리·무승부 문구, 로비로 돌아가기
    - 빌드 순서가 Lobby·Game·Result인지
    - LobbyScene과 ResultScene의 참조
  - `BattleViewTests` (+3 / −4)
    - 게임 화면에 설정 패널이 없고 "See Results" 버튼이 있음
    - 게임이 끝나기 전에는 결과 요청이 무시되고, 끝난 뒤에는 이벤트가 나감
- 씬 생성: `-executeMethod DRG.EditorTools.GameSceneBuilder.Build`. 세 씬 모두 PanelSettings, UXML, 화면 스크립트 참조를 확인했다.
- Windows 플레이어 빌드: `build5/DRG.exe`, `Build Finished, Result: Success`
  - 빌드할 때 Unity가 다시 저장한 관계없는 설정 파일 5개는 되돌렸다.
  - 화면 없이 10초 실행했고 예외나 오류 로그가 없었다(첫 씬은 LobbyScene).
- **확인하지 못한 것**: 실제 화면에서 로비 → 게임 → 결과 → 로비를 클릭으로 이어가는 흐름과 배치. 씬 전환은 Play 모드에서만 일어나서 EditMode 테스트로는 확인할 수 없다.
