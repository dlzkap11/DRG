# 06. M2: 2인 UI (Human 1 + Bot 1)

- 날짜: 2026-09-28
- 브랜치: `feature/m2-two-player-ui`
- 마일스톤: M2 2인 UI
- 기준: 명세서 §15~§18 UI, §24 STEP 5~6 / 기획서 §8 정보 공개 / `CLAUDE.md` §5·§6·§9 / DEC-007

## 목표
사람 1명이 봇 1명과 실제 화면에서 한 판을 끝까지 플레이할 수 있게 한다.
- 행동 선택과 대상 선택
- Lock
- 행동 공개
- 전투 로그
- 승패 표시와 다시 하기

## 작업 전에 확정한 사항 (프로젝트 소유자 결정 → DEC-007)
| 질문 | 결정 |
|---|---|
| UI 방식 | UI Toolkit (UXML/USS). 씬과 PanelSettings는 에디터 스크립트로 생성한다. |
| 상대 봇 | M3 BotAI 전까지 무작위 선택기(`RandomActionPolicy`)를 사용한다. 사람과 같은 Lock 경로를 쓴다. |
| 화면 언어 | 영어. 기본 폰트에 한글이 없어서, 한글 폰트는 나중에 추가한다. |
| 연출 | 기능 위주의 최소 화면. 애니메이션과 이펙트는 넣지 않는다. |

## 구조
```text
[UXML 버튼] → BattleView (Lock 전 임시 선택만 보관)
            → LocalBattleSession.SubmitHumanAction → TurnManager.Lock (ActionValidator)
BotPlayer (RandomActionPolicy) ──────────→ TurnManager.Lock  ← 사람과 같은 경로
전원 Lock → TurnManager.StartResolution → BattleResolver → BattleResult
          → BattleView.Refresh: 공개, 로그, 승패 표시
```
- **Human과 Bot 통합**: 둘 다 `PlayerAction`을 만들어 `TurnManager.Lock`으로 확정한다. 전투 코드에는 사람인지 봇인지 구분하는 분기가 없다(`CLAUDE.md` §6).
- **UI는 게임 상태를 바꾸지 않음**:
  - `BattleView`가 들고 있는 것은 "고른 행동과 대상" 같은 **Lock 전 임시 선택**뿐이다.
  - HP, Ki, 행동 확정은 모두 `LocalBattleSession`을 거쳐 게임 로직이 처리한다.
  - 버튼 활성화 여부는 `ActionValidator`의 결과로 정하고, Lock할 때 한 번 더 검증한다.
- **정보 공개 규칙** (기획서 §8):
  - `GetVisibleAction`은 공개 전에는 상대의 행동을 `null`로 돌려준다. 화면에는 "? (hidden)"으로 표시된다.
  - 돌려주는 값은 복사본이라, UI가 바꿔도 Lock된 행동에는 영향이 없다.
- **턴 흐름**:
  1. 턴이 시작되면 봇이 먼저 Lock한다. 봇의 행동은 숨겨진다.
  2. 사람이 Lock하면 전원이 Lock된 상태가 되어 바로 전투를 처리하고 결과를 공개한다.
  3. "Next Turn" 버튼으로 다음 턴을 시작한다.
  - 사람이 탈락했는데 게임이 계속되는 경우(3인 이상)에는 봇만으로 턴이 바로 처리된다.
- **BattlePresentation**: 이번에는 연출이 없어서 별도 클래스를 만들지 않았다. `BattleView`가 `BattleResult`를 텍스트(공개 패널과 로그)로 보여주는 것이 표시 단계의 전부다. 연출이 필요해지면 이 자리에 추가한다.
- **씬 자동 생성**: `GameSceneBuilder`가 PanelSettings(기본 런타임 테마, 1280×720 기준), 카메라, UIDocument와 `BattleScreen` 오브젝트를 만들고 빌드 목록 첫 번째에 등록한다. 씬 파일을 손으로 편집하지 않는다.
- **입력**: 프로젝트는 Input System만 사용하도록 설정돼 있다(`activeInputHandler: 1`). Unity 6.3 UI Toolkit은 이 설정에서도 EventSystem 없이 입력을 받는다(`InputSystemCompatibleBackend`). 그래서 EventSystem은 추가하지 않았다.

## 화면 구성
- 상단: 턴 번호와 현재 단계 ("Choose your action and lock it" / "Actions revealed" / "Game over")
- 플레이어 카드: 이름, HP, Ki, 상태(Choosing / Locked / Eliminated), 행동(공개 전 상대는 "? (hidden)")
- Actions: 행동 5개 버튼. 쓸 수 없는 행동은 비활성화된다. 고른 버튼은 강조된다.
- Choose a target: 공격을 골랐을 때만 표시된다. 대상으로 고를 수 있는 상대만 버튼으로 나온다.
- 선택 상태와 Lock 버튼: 공격은 대상을 골라야 Lock할 수 있다.
- Reveal: 이번 턴의 행동과 판정 결과, 그리고 "Next Turn" 버튼
- Game over: "You win!" / "Bot 1 wins. You lose." / "Draw - no survivors.", 그리고 "Play Again" 버튼
- Battle Log: 최근 턴이 위에 온다.

## 검증
- EditMode 테스트: **112개 중 112개 통과** (기존 88 + 이번 24), 컴파일 오류·경고 0건
  - `LocalBattleSessionTests` (11)
    - 봇이 먼저 Lock하고 사람을 기다림
    - 공개 전에는 상대 행동이 숨겨짐
    - 사람이 Lock하면 바로 처리되고 공개됨
    - 잘못된 행동은 거부되고 턴이 처리되지 않음
    - 공개되는 행동은 복사본임
    - 다음 턴 진행
    - 사람이 탈락해도 봇끼리 턴이 처리됨
    - 한 판을 끝까지 진행하면 게임 종료 후 다음 턴이 막힘
    - 봇 수 범위 검사
  - `BattleLogFormatterTests` (5): 행동과 판정 문장, 탈락과 승자, 무승부, 탈락자의 None 행동 생략, 행동 이름
  - `BattleViewTests` (8): **실제 `BattleScreen.uxml`을 불러와** 다음을 확인했다.
    - 초기 화면(턴, 숨겨진 상대 행동, 카드 상태)
    - 쓸 수 있는 행동만 버튼이 활성화됨
    - 쓸 수 없는 행동을 고르면 무시됨
    - 고르고 Lock하면 공개 패널과 로그가 표시됨
    - 다음 턴
    - 공격은 대상을 골라야 Lock 가능하고, 자기 자신은 대상 목록에 없음
    - 끝까지 진행하면 게임 종료 패널이 표시됨
    - 생성된 GameScene의 참조(PanelSettings, 테마, UXML, 빌드 목록 첫 번째)
- 씬 생성: `-executeMethod DRG.EditorTools.GameSceneBuilder.Build` 실행 성공. 씬 파일의 UIDocument가 PanelSettings와 UXML을, 오브젝트가 BattleScreen 스크립트를 올바르게 참조하는 것을 확인했다.
- Windows 플레이어 빌드: `-buildWindows64Player`로 빌드했다(임시 폴더). `Build Finished, Result: Success`.
  - 빌드하면서 Unity가 URP 셰이더 최적화 설정 등 관계없는 설정 파일 5개를 다시 저장했다. 이번 작업과 관계없어서 원래대로 되돌렸다.
- 빌드한 플레이어를 화면 없이 10초 실행했다(`-batchmode -nographics`). 씬이 로드됐고 예외나 오류 로그가 없었다.
- **확인하지 못한 것**:
  - 실제 화면이 어떻게 보이는지(배치, 글자 크기, 색)
  - 마우스 클릭이 버튼 이벤트로 이어지는지
  - 테스트는 `BattleView`의 공개 메서드로 조작을 흉내 냈다. 버튼과 메서드의 연결(`clicked +=`)은 코드로만 확인했다.
  - 에디터에서 Play를 누르거나 빌드를 직접 실행해서 확인해야 한다.

## 실행 방법
1. Unity 에디터에서 `Assets/_Project/Scenes/GameScene.unity`를 열고 Play를 누른다.
2. 씬을 다시 만들어야 하면 메뉴 `DRG > Build Game Scene`을 실행한다.
