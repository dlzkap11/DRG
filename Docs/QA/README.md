# DRG QA 문서

게임이 기획서, 명세서, `DECISIONS.md`대로 동작하는지 사람이 확인할 때 쓰는 문서를 모아 두는 폴더입니다.

- 이 폴더는 **확인 방법과 결과**만 기록합니다. 게임 규칙을 정하지 않습니다.
- 규칙의 기준은 기획서, 명세서, `DECISIONS.md`입니다.
- 확인하다가 규칙이 정해지지 않은 부분을 발견하면, 여기서 정하지 않고 `Docs/PROGRESS.md`의 "Known Design Questions"에 기록합니다.
- 작업 기록은 `Docs/DevLog/`, 마일스톤 상태는 `Docs/PROGRESS.md`에서 관리합니다.

## 사용 방법
1. 확인할 빌드 폴더와 커밋을 적습니다.
2. 문서의 결과 칸을 채웁니다: `통과` / `실패` / `확인 못 함` / `설계 질문`.
3. `실패`는 아래 양식으로 버그를 기록합니다.
4. `설계 질문`은 `Docs/PROGRESS.md`에 옮깁니다.
5. 다 채운 문서는 파일 이름에 날짜를 붙여 복사해 두거나, 해당 DevLog에 결과를 요약합니다.

## 버그 리포트 양식
```text
제목:
빌드: (예: build3/DRG.exe, 커밋 해시)
화면 크기 / 전체 화면 여부:
관련 케이스 ID: (예: UI-07, M3-B03)

재현 단계:
1.
2.
3.

기대 결과: (근거 문서와 절 번호, 예: 명세서 §26, CLAUDE.md §8)
실제 결과:
재현 빈도: (항상 / 가끔 N번 중 M번 / 한 번만)
전투 로그: (해당 턴의 로그 줄을 그대로 복사)
스크린샷:
심각도: 치명(진행 불가) / 높음(규칙 오류) / 보통(표시 오류) / 낮음(문구, 배치)
```

### 재현에 대한 주의
- 봇은 seed로 행동을 정합니다. 그래서 seed를 알면 같은 판을 다시 만들 수 있습니다.
- 하지만 현재 빌드는 seed를 시작 시각(`Environment.TickCount`)으로 정하고 화면에 보여 주지 않습니다(`BattleScreen.cs`). 빌드에서 발견한 버그를 같은 seed로 다시 재현할 방법은 아직 없습니다.
- 그러므로 당분간은 **전투 로그를 빠짐없이 복사**하는 것이 가장 좋은 재현 자료입니다. 로그에는 턴마다 모든 플레이어의 행동과 판정이 남습니다.
- seed를 화면이나 로그에 보여 줄지는 아직 정하지 않았습니다(`PROGRESS.md`에 기록).
